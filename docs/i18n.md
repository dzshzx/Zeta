# 多语言

Zeta 的界面有简体中文和英文两种。简体中文是源语言：代码里先写中文，文字表里有每一条；英文是译文，缺的条目显示中文。界面默认跟随系统语言（系统语言不是这两种之一时用简体中文），设置「常规」里能改成某一种，手机和桌面各存各的。

## 文字表

三端都用 mygo 的文字表格式（见 mygo 文档的 `docs/i18n.md`）：每种语言一个 ARB 格式的 JSON（`zh-Hans.json`、`en.json`），键是小驼峰的英文名，值是 ICU MessageFormat 消息（`{name}` 占位，`{count, plural, one {…} other {…}}` 复数）；源语言的文件在 `@键` 下写说明（`description`，说在哪显示）和占位的类型（`placeholders`）。英文要注意复数，中文只有 `other`。

| 文字表 | 谁用 | 生成什么 |
|---|---|---|
| `helper/locales/` | 核心（按请求的语言出应答里的字），两个客户端（按核心给的种类码出共享状态里的字） | Go 取字函数（核心和桌面版用），Kotlin 的 `CoreStrings`（手机版用） |
| `windows/internal/locales/` | 桌面版界面 | Go 取字函数，`go tool mygo generate`（`windows/mygo.json` 的 `i18n`） |
| `app/src/main/locales/` | 手机版界面（`app/` 和 `shared/` 里的都用它） | Kotlin 的 `Strings` |

同一句话只在一个文字表里：核心定义了种类码的文字（提示、状态、额度窗口名、确认卡说明）在核心的文字表里，两个客户端都从那里取；只属于一端界面的在那一端的文字表里。

生成的代码（`catalog_gen.go`、Kotlin 的取字对象）和文字表一起提交；门禁（`scripts/check.sh` 的 `check_catalogs`）核对文字表：消息能解析、英文的占位和源语言一致、每句都有英文，生成的代码和文字表对得上。

Kotlin 的取字对象由 `helper/cmd/ktlocales` 生成（在 `helper/` 下 `go run ./cmd/ktlocales`），写成 `shared/src/commonMain/kotlin/com/dzshzx/zeta/i18n/` 下的 `Strings.gen.kt`、`CoreStrings.gen.kt`：每个键一个函数，参数类型照 `placeholders`（没写的照 mygo 推断）。生成的文件不经 ktfmt 排版、不计行数上限（`scripts/format.conf`）。手机版文字表的核对靠 `app/mygo.json`（只给 `mygo i18n check` 用，不用 mygo 生成 Go 代码）。

## 哪些不翻译

- Claude Code、MCP 服务器、远程主机命令原样给的文字（报错原文、工具输出、计划、提问内容）。
- 交给 Claude Code 或写进主机文件的文字：给 Claude 的工具说明和提示、`--name` 写进会话记录的标题、托管脚本和 tmux 窗口里的输出、和脚本对暗号的标记（`cwdProblemMark`）。
- 日志和只进日志的内部错误。
- 手机工具的结果要借用界面那边的取字函数（比如定时任务的规则说明）时，在 `UiLanguage.forClaude { … }` 里出字：这个线程上固定用源语言。

## 核心

客户端连上核心时发的 `core.client` 带 `lang`（`zh-Hans` 或 `en`，客户端界面当前的语言；以后切换语言时再发一次），两个客户端每次连上都发。核心记在这条连接上（`core.Client.Lang()`）。

- 只回给发请求那个客户端的（出错应答的 message、导出的 Markdown、搜索片段、配置页的说明表）：核心按这条连接的语言出字。出错应答同时带 `code` 和 `args`，客户端要按种类处理时看 `code`，不比对文字。
- 推给所有客户端的共享状态（对话条目里的提示、状态、确认卡的说明、任务清单兜底标题、额度窗口名、会话列表的「图片」预览）：核心发种类码和参数（例如提示条目的 `code`、`args`，状态的 `status_code`、`status_args`；全部的码见「核心种类码清单」），客户端用核心文字表的取字函数出字；`text` 仍按源语言写着，给不认识这个码的旧客户端。只翻译前缀的（「Claude Code 拒绝了这次操作：」加原文），种类码加 `detail` 原文。
- 会存下来的数据（分支标题「分支 · 原标题」、新对话的临时标题）用发起操作那个客户端的语言写；认它们的正则两种语言都认。
- 客户端不比对核心给的文字，要认的东西用结构字段：会话记录里过长的字符串截断处只加不分语言的「\n…」，改文件的工具参数被截断时步骤带 `clipped`，客户端看它判断对比不全。

## 客户端

- 桌面版：`windows/internal/locales` 由 mygo 管：语言协商、`App.SetLocale` 切换并记住、`App.OnLocaleChanged` 后重画。mygo 自带的文字（菜单、输入框菜单）跟着用同一种语言。
- 手机版：语言照 Android 的应用语言（框架的 `LocaleManager`，不用 AppCompat；`res/xml/locales_config.xml` 让系统设置的「应用语言」里也能改），没单独设时跟随系统。`app` 的 `AppLanguage` 在进程起来时（`ZetaApp`）和每次配置变化时定下语言，写进 `shared` 的 `UiLanguage.current`；变了就让开着的核心连接再报一次 `core.client`（`HelperServe.introduceAll`）。界面随 Android 重建 Activity 换语言。设置首页「通用」一组最上面是「语言」一行。
  - 出字：两份文字表构建时放成包里的 Java 资源 `locales/<core|app>/<语言>.json`（`app/build.gradle.kts` 的 `catalogResources`；两份的文件同名，所以不直接设成资源目录），`Catalog` 经类加载器读，不要 Context；格式化用 `android.icu.text.MessageFormat`（`IcuMessageFormatter`），缺的句子退回简体中文。
  - 提示条目（`NoticeItem`）有 `code` 时用 `said()` 按界面语言出字，没有时是 `text`；按种类处理的地方比 `code`，不比文字。
  - 测试：测试的 Application 把界面语言固定成简体中文（Robolectric 的系统语言是英语）。不带 Robolectric 的测试里 `android.icu` 是空壳，单元测试另登记一个用 ICU4J 的格式化（`app/src/test/resources/META-INF/services`），`AppLanguageTest` 核对两者对全部文字表出的字一样。

## 怎么加一句话

1. 在对应文字表的 `zh-Hans.json` 加键、源语言文字和 `@键` 的说明；`en.json` 加英文。
2. 重新生成：桌面版 `cd windows && go tool mygo generate`；核心 `cd windows && go tool mygo generate ../helper`；手机版（含核心的 Kotlin 那份）`cd helper && go run ./cmd/ktlocales`。
3. 代码里调生成的函数（Go 是 `locales.SettingsLanguage()`，Kotlin 是 `Strings.settingsLanguage()`），不写中文字面量。界面上的字从文字表来；测试按当前语言断言，或固定一种语言跑。

## 核心种类码清单

推给所有客户端的共享状态里，核心自己说的话都带种类码（核心文字表 `helper/locales` 的键）和参数；同一个对象里仍有源语言的文字字段，给不认识种类码的旧客户端。客户端有种类码时用核心文字表按自己的界面语言出字，没有时照文字字段原样显示（那是 Claude Code、MCP 服务器或用户的原文）。参数的值是字符串或数；值是带 `code` 的对象（`{"code","args"}`）时是嵌着的一句话，先按同一种语言说出来再代进去（`noticeNotSent`、`noticeNotDeleted`、`forkFailed` 的 `reason` 会这样）。桌面版的出字都在 Go 里（`locales.Msg.In`，嵌着的话它会处理），下表的「桌面版取字」是现成的方法。

| 在哪 | 字段 | 种类码 | 什么时候 | 桌面版取字 |
|---|---|---|---|---|
| `conv.items` 里 `kind` 为 `notice` 的条目 | `code`、`args`（文字 `text`） | `noticeStopped`、`noticeSteered`、`noticeContextCleared`、`noticeCompacted`、`noticeAutoCompacted`、`noticeCompactedFrom`、`noticeAutoCompactedFrom`（`tokens`）、`noticeTurnAbnormal`（`subtype`）、`noticeStartFailed`（`reason`）、`noticeNoWorkDir`（`cwd`）、`noticeClaudeNotStarted`、`noticeClaudeKilled`、`noticeClaudeExited`（`code`）、`noticeClaudeExitedDetail`（`code`、`detail`）、`noticeHandedToTerminal`、`noticeNotDeleted`（`reason`）、`noticeNotSent`（`reason`）、`noticeCodeRestored`、`noticeForkStarted`、`noticeShellWhileBusy`、`noticeShellRunning`、`noticeReattachFailed`（`reason`）、`noticeHistoryFailed`（`reason`），以及还原代码没成时直接用的 `restore*`、`rewind*` | 对话里的灰色提示和出错提示；Claude Code 给的出错原文没有 `code` | `items.Item.Said` |
| `conv.items` 里工作组的一步（`steps` 的一项） | `result_code`、`result_args`（文字 `result`） | `stepInterrupted`、`stepShellNoOutput`、`stepShellExit`（`output`、`code`）、`stepShellNoOutputExit`（`code`） | 工具没跑完就停了；输入栏 `!` 命令没有输出或退出码不为 0。工具自己的结果没有 `result_code` | `items.Step.ResultSaid` |
| `conv.state` | `status_code`、`status_args`（文字 `status`） | `statusCompacting`、`statusRetrying`（`attempt`，不知道时为 0） | 等待指示旁的那句；没有时 `status_code` 为空 | `chat.State.StatusIn` |
| `conv.state` 的 `prompts` 每一项 | `notice_code`、`notice_args`（文字 `notice`） | `promptMcpUrl`、`promptMcpForm`（`server`）、`promptPlan`、`promptQuestion`、`promptTool`（`tool`） | 等你回应的通知那一句 | `prompt.Prompt.NoticeIn` |
| 同上 | `suggestion_msgs`：`[{code, args}]`，和 `suggestion_lines` 一一对应 | `suggestRule`（`behavior`、`target`、`where`）、`suggestDirectory`（`dir`、`where`）、`suggestMode`（`mode`）、`suggestOther`（`type`） | 确认卡「以后不再询问」列的几条；`behavior`、`where`、`mode` 是 Claude Code 的原值，由文字表里的 `select` 分情况 | `prompt.Prompt.SuggestionLinesIn` |
| 同上 | `agent_label_code`（文字 `agent_label`） | `promptBackgroundSubagent` | 后台子代理发起的确认，找不到它的说明时；用的是说明原文时为空 | `prompt.Prompt.AgentLabelIn` |
| `conv.state` 的 `todos` 每一项 | `content_code`（文字 `content`；参数 `id` 就是这一项的 `key`） | `todoUntitled` | Claude 没给标题的任务；`active_form` 和 `content` 相同时它也跟着换 | `sessionproto.Todo.ContentIn`、`ActiveFormIn` |
| `conv.turn` | `code`（文字 `text`） | `turnDone`、`turnStopped`、`turnFailed`、`turnInterrupted` | 一轮结束，和 `outcome` 一一对应 | `chat.Turn.Said` |
| 额度（`quota.*` 的 snapshot、额度推送）里的每个窗口 | `labelCode`（文字 `label`；参数 `scope` 就是窗口的 `scope`） | `quotaSession`、`quotaWeeklyAll`、`quotaWeeklyScoped`、`quotaWeekly` | 窗口名；按模型分、名字是服务器原文的窗口没有 | `coreapi.QuotaWindow.LabelIn` |
| 会话列表（`zeta_sessions` 的每一项、`sessions.lookup`） | `preview_code`（文字 `preview`） | `previewImage` | 第一句话只有图；预览是用户原话时为空 | `hub.SessionLabel` |
| `conv.task_output` 的结果和推送 | `error_code`（文字 `error`） | `taskNoOutput` | 读后台输出没成、Claude Code 没说原因 | `tasks.Output.ErrorIn` |

只回给发请求那个客户端的（出错应答的 `error`、导出的 Markdown 和文件名、搜索片段、工具权限页的工具说明、MCP 表单各项的错误、`accounts.list` 的 `blocker`）核心已经按这条连接 `core.client` 报的 `lang` 写好，客户端照原样显示；出错应答另带的 `code` 是种类码，只在要按种类处理时看。
